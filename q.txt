fix(scripts): sharp takes 1-100 quality, canvas.toBlob takes 0-1

The report run found all 54 rows and downloaded every one, then sharp
rejected the quality on every single row:

    Expected integer between 1 and 100 for quality but received 0.72

productImages.ts encodes in the browser with canvas.toBlob, which takes
a 0-1 float, so the same 72% quality is spelled 0.72 there. sharp wants
72. The constant was copied across verbatim and the unit was never
converted, so the job re-encoded nothing.

This is the exact encoder-divergence the file's own header warns about,
and it shipped in the first commit of the job - the header described
the risk more clearly than the code respected it. The value is now 72
with a comment naming both units, so the next reader does not copy 0.72
back in.

Report mode is what caught it: 54 failures, zero writes, no cleanup.
Verified by re-running: 54 ok, 0 failed.
