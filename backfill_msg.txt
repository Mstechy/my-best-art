feat(scripts): backfill missing 320px card derivatives

54 of 91 product images predate the feed's phone variant and still
serve the 900px asset at ~462KB, which is most of the homepage weight.
Supabase Image Transforms return 403 FeatureNotEnabled on this project
and the browser already had a canvas encoder, so this backfills the gap
in Node with sharp instead.

Mirrors backfillImageDimensions.ts: same keyset paging on id=gt., same
bounded concurrency, same report-don't-skip-failure contract, same
service-role read that is never logged. It reuses the exact recipe from
uploadProductImagePair - 320px, WebP, q0.72, card320-<stem>.webp beside
the original - so the bucket does not end up holding two subtly
different small-card formats depending on when a listing was uploaded.

Defaults to report mode and writes nothing; --apply is required to
change the database. Safe to re-run: it only selects rows whose
card_small_url is still NULL.

sharp is a devDependency and never enters the browser bundle.
Build and lint verified; typecheck does not cover scripts/ so the
script was run directly to confirm it loads and reports correctly.
